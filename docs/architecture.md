# Architecture

The acquire → normalize flow, the Pattern contract that makes it extensible, and how to add a new source.

pagespring *acquires*; pagespeak *converts*. This doc covers the acquisition half only — everything upstream of the clean file in `incoming/<slug>/`.

## The pipeline

One command, `ingest`, drives `run_ingest` in `orchestrate.py`:

1. **classify** — `registry.classify(url)` walks the registered patterns and returns the first whose `match()` accepts the URL (or raises `NoPatternError`).
2. **acquire** — the pattern downloads the raw pages into a temp workdir and returns an `AcquireResult` (raw dir, source kind, slug, page count, and an optional human `title` for the deliverable heading — falls back to the slug).
3. **normalize** — the pattern turns the raw pages into ONE clean file (`.html` / `.md` / `.pdf`) with **absolute** asset URLs — except files no URL serves (an EPUB's own figures), which the pattern copies into `images/` beside the file (`base.IMAGES_DIR`) and refs as `images/<name>`. Keep what a reader sees, not what the markup holds: rebuild a formula MathJax drew as SVG glyphs as MathML (`_mathjax.rebuild_math`) and flatten a shiki block's per-token spans to plain code with its language (`_shiki.flatten_shiki`); `_readable.clean` applies both.
4. **stage** — `run_ingest` guards the slug, writes the manifest, writes the clean file atomically, and only then clears `incoming/<slug>/` of what it replaced (keeping the image cache on a same-source re-ingest; a slug holding a *different* source — or content with no readable manifest — is refused rather than cleared unless `--replace`, which drops the cache with the manual it belongs to; so is a same-source re-crawl whose `pages` falls below `COLLAPSE_KEEP_PCT` percent of the staged manual's, because a restructured source still normalizes to a non-empty shell), then copies `raw/`, copies any images the pattern bundled into `incoming/<slug>/images/` (`_staging.stage_bundled_images`: a localize record under a bundled name is dropped, and files the deliverable no longer references are pruned), and finalizes the `manifest.json` (see [The manifest](#the-manifest)). Do not reorder these: clearing before the new file lands lets a kill or a full disk destroy the only copy, and content with no manifest reads as a foreign manual on the next ingest.

Every slug — the one acquire derived or a `--slug` override — passes through `paths.fold_slug` before it names anything: slugified, then capped at 100 characters with the trailing dash trimmed. The fold is fed by remote titles, and an uncapped one names a file no filesystem will create.

All work happens in a temp dir; only the final clean file (plus its `manifest.json`, and optionally `raw/`, `images/`) lands in `incoming/`. Empty normalize output raises `EmptyOutputError` *before* the staging clear, so a bad re-crawl never destroys a prior good deliverable.

**Normalize flattens responsive images first.** The localizer follows `<img src>` and markdown `](…)` only, so any reference parked in `<picture>`/`<source srcset>`, `srcset`/`data-srcset`, or a `data-src` lazy-load attribute is invisible to it and ships remote no matter how often `localize` runs. `_site.flatten_responsive_images` reduces each image to one plain `<img src>`, resolving a winner **before** deleting any carrier. The winner is the **widest declared rendition** — a `srcset` `w`/`x` descriptor, or a CDN sizing parameter (`wid=`, `width=`) — because the deliverable feeds a vision pass, so resolution is the point. With no widths declared anywhere it falls back to `src`, then `data-src`, then an arbitrary `srcset` candidate (the tie breaks on the URL string, not document order).

Three traps drove that design. Publishers park a transparent `data:` spacer in `src` with the real URL in `data-src`, so preferring `src` blanks the figure. A `data:` URI contains its own comma, so splitting a srcset on commas yields base64 fragments that look like relative URLs. And a `<source>` behind `media="(not all)"` — a query that can never match — holds a variant the page never renders (Apple's dark-mode asset), so it must be excluded from ranking rather than treated as a better candidate.

Call it before `absolutize_refs`: a promoted `data-src` is usually page-relative. An `<img>` with no usable reference is dropped rather than staged empty, and an already-localized `images/…` ref is never swapped back to a remote rendition.

**Image refs are decoded before fetching.** The localizer matches refs by regex over the raw markup, so `&` arrives as `&amp;`. Fetched escaped, a CDN reads `amp;wid=1199` as an unknown parameter and serves its small default — the Adobe manuals localized at 400px for exactly this reason. `images.py` unescapes at the fetch boundary and keys the sidecar on the decoded URL.

**Image localization is a decoupled step.** Because normalize leaves asset URLs **absolute**, a no-image deliverable is already complete (pagespeak can fetch those URLs at convert time). Images can be pulled either inline (`ingest --download-images`) or after the fact (`pagespring localize <slug>` → `localize.localize_images`), both downloading into `incoming/<slug>/images/` and re-pointing refs. `localize` is **resumable** — it re-points each image as it lands and checkpoints the file — so a book whose image set exceeds one run's budget is finished by re-running until none remain. `images.py` is a shim over `pf_core.fetch.images`, keeping pagespring's on-disk naming (sanitized basename, `-2`/`-3` on collision) and routing downloads through `pagespring.http` so they carry the crawl UA and delay.

**Refresh is a sweep of step-1-to-4 re-runs, driven by the manifests.** `pagespring refresh [<slug>...|--all|--pattern <name>]` (→ `refresh.py`) re-ingests each slug from its manifest's `source_url` with `--if-changed` semantics, isolating per-slug failures so one dead source can't stop the sweep, preserving the kept-raw property, pinning the recorded slug (a retitled source or `--slug` override never mints a duplicate dir), and reporting each outcome (`changed`/`unchanged`/`failed`/`skipped`). Patterns that declare `single_fetch = True` (the deliverable derives from exactly the one recorded URL — `audit`'s `single_page_crawl` check reads the same flag, a one-URL deliverable never being a collapsed crawl) get a fast path first, as does any PDF deliverable whichever pattern routed it (`docs_probe` hands a PDF served from an extensionless path to `pdf_url`): when the acquire captured the response's `ETag`/`Last-Modified` into the manifest, refresh probes with one conditional GET (`http.not_modified`) — a definitive 304, or a 200 carrying the same strong `ETag` (some servers ignore conditional headers), reports `unchanged` with no re-download; anything else, a manifest with no validators included, falls through to the full path. A full re-fetch that normalizes to the same bytes still records the validators it was served, so a source that re-stamps an identical file answers 304 on the next sweep. Crawl patterns never probe: an entry page's validators prove nothing about the rest of a site.

**Renormalize is an offline replay of steps 3–4.** `pagespring renormalize <slug>` (→ `renormalize.run_renormalize`) re-runs the pattern's **current** `normalize()` against the kept `incoming/<slug>/raw/` — no classify, no acquire, no network. The `AcquireResult` is reconstructed from the manifest (pattern by recorded name, kind/slug/pages/title/lost — normalize may derive `lost`, and the replay writes it back, so a pattern's normalize must stay idempotent over a seeded `lost`), and raw is copied into a fresh workdir so a normalize that mutates its input can't corrupt the kept copy. Byte-identical output over an intact staged file re-stages nothing and reports `unchanged` — the signal that a normalize refactor was behavior-preserving; a missing or altered staged file is re-staged. Changed output replaces the deliverable, clears any stale `images/` (a re-localize would otherwise collide into suffixed names; figures the pattern bundles are re-staged from the kept raw), and refreshes the manifest's content facts (`sha256`, `bytes`, `deliverable`, `images` reset to 0 — refs are absolute again) while crawl provenance (`source_url`, `ingested_at`, `pages`) is untouched. Requires an ingest made with `--keep-raw`; the manifest's `kept_raw` records whether that happened, read from the staged directory so it cannot promise a replay that isn't there. `--keep-raw` is ignored for PDF deliverables — `pdf_url.normalize` returns the downloaded file unchanged, so a replay can only reproduce the staged bytes.

## The manifest

Every staged deliverable gets a sibling `incoming/<slug>/manifest.json` (`manifest.py`) — the provenance record that makes the pagespeak hand-off self-describing:

```json
{
  "schema_version": 7,
  "pagespring_version": "0.14.0",
  "source_url": "https://docs.tableplus.com/",
  "pattern": "docs_probe",
  "slug": "tableplus",
  "kind": "markdown",
  "title": "TablePlus Documentation",
  "etag": null,
  "last_modified": null,
  "truncated": false,
  "single_document": false,
  "kept_raw": false,
  "lost": 0,
  "localized_sha256": null,
  "deliverable": "tableplus.md",
  "pages": 62,
  "bytes": 123456,
  "sha256": "…",
  "images": 0,
  "ingested_at": "2026-06-14T17:23:01Z"
}
```

Schema v2 added `title` (acquire's source title, feeding `renormalize` replays); v3 added `etag`/`last_modified` (response validators from single-fetch acquires, feeding `refresh`'s conditional-GET probe); v4 added `truncated`; v6 added `lost` (pages discovered but never staged — `truncated` only ever meant the page *cap*, so a crawl losing pages to throttling looked complete), `single_document` — the source **is** one article, so a `pages: 1` deliverable is correct rather than a crawl that collapsed onto its seed (`audit`'s `single_page_crawl` check reads it) — `kept_raw`, recorded from the staged directory rather than the flag, so a manifest can never promise a `renormalize` replay that isn't on disk, and `localized_sha256`; v7 added `image_pass_open`, present only while an image pass is open, so a killed pass resumes instead of reading as damage. `status` marks kept-raw slugs `raw`. Read the post-v1 keys with `.get` — older files lack them.

**v5 dropped `convert_recipe`** — the sole non-additive change. Every remaining field states what the source *is*; none instructs the converter. Do not add a field that does: pagespring cannot see pagespeak's flags, so a hint staged here goes stale silently the moment pagespeak's evidence or CLI moves, and nothing fails loudly when it does. pagespeak derives conversion settings from `kind`, `pattern`, and the deliverable itself.

`source_url` is the identity every later run compares against — `refresh` replays it and the slug-takeover guard canonicalizes it — so a **local** source records its resolved absolute path rather than the argument as typed, which names a different file from every other working directory.

`sha256` is the hash of the deliverable **as `normalize()` produced it** (before `--download-images` re-points any refs) — so on the default path it matches the on-disk file, and it stays stable as the content's identity regardless of image-localization. `localized_sha256` is the companion: the hash of the file **as it stands after** an image pass re-pointed its refs, refreshed by every pass and reset to `null` by `renormalize`. `audit` checks whichever of the two describes the bytes on disk, so a localized deliverable — the most-processed kind — still has an integrity record rather than none. A deliverable whose pattern bundled images records `localized_sha256 = sha256` at staging: its refs are local from the start, and only that hash lets `audit` and `--if-changed` tell damage from an image pass.

That hash is what `ingest --if-changed` compares against: a re-crawl that normalizes to the same bytes leaves the existing `incoming/<slug>/` untouched (file, images, mtime) and reports `unchanged` — but only while the recorded `deliverable` is still on disk, since a sha describes a file that has to be there to be kept. The crawl itself still runs — the slug is only known after `acquire`, so `--if-changed` saves the re-stage and churn, not the network round-trip. `status` reads these manifests; legacy dirs without one fall back to the deliverable file's own facts.

## The Pattern contract

A pattern is one source type's knowledge, as a class implementing the `Pattern` protocol (`base.py`). Four members:

- `name` — the registry id (`apple_help`, `gitbook`, …).
- `match(url)` — cheap host/path check, returns bool.
- `acquire(url, workdir)` — download raw pages, return an `AcquireResult`.
- `normalize(acq, workdir)` — merge/clean into one file, return its path.

The `acquire`/`normalize` split is the key design rule: `acquire` holds all network and source-shape knowledge; `normalize` is pure transformation over local files. That split is what lets tests mock `pagespring.http` and exercise both halves with no network.

## Classification order

First match wins, so registration order in `registry.py` is load-bearing. Four tiers, cheapest/most-specific first:

1. **Host-specific** patterns (e.g. `apple_help`, `readthedocs`, `github_markdown`) — they recognise a known host. RTD projects without PDF builds fall back to a Sphinx crawl instead of failing. A host-specific `match` must **decline** a URL on its own host that names a file another tier owns: `github_markdown` takes only a repo root, a `/tree/` URL, or a `/blob/` URL naming a `.md` file (scoping the crawl to that file's directory on that branch), leaving release assets, `/raw/` files and source archives to the pattern for their type; `readthedocs` likewise leaves spec, archive and PDF file URLs alone, and maps a `/projects/<alias>/` subproject URL to that subproject's own build at the URL's version.
2. **Extension / content** patterns — `api_spec` (a `.json`/`.yaml`/`.yml` extension, or an `openapi`/`swagger`/`postman` token in the last path segment), then `pdf_url` (a `.pdf` path or a Read the Docs `/_/downloads/…/pdf/` build — never a bare `/pdf` path, which is usually a docs section; `docs_probe` hands any other PDF to it, including a body too large for the text budget), `archive_download`, then `sitemap_crawl`, which claims only a URL naming a sitemap file (`sitemap.xml`, `sitemap-index.xml`, …) and crawls the pages it lists under its directory, extracting each page's main content — opt-in by construction, since nothing else routes to it — so a spec or a `.pdf` routes here rather than falling through to a broader pattern below.
3. **`gitbook`**, narrowed to its own hosting (`*.gitbook.io`) — custom-domain GitBook sites carry no URL tell, so they fall through to `docs_probe` instead.
4. **`docs_probe` last** — a content-probing catch-all that claims any http(s) URL nothing above it matched. Its `match` is nearly free (scheme check only); all the real classification work happens in `_detect.detect`, which `acquire` runs before handing off and `classify --probe` runs alone. It probes the base page in order — `%PDF-` magic bytes first (a vendor may serve the manual itself as a PDF from an extensionless path, which `pdf_url.match` cannot see), then an OpenAPI document served from an extensionless path (springdoc's `/v3/api-docs/<group>`, handed to `api_spec` with the body already fetched; it must carry a version and `paths`/`components`, since an API root's `{"openapi": "/openapi.json"}` only links to the spec), then an API reference UI (Swagger UI, Redoc, Scalar — detected by the UI's own element or script, never by the words on a page), whose one named, parse-proven spec goes to `api_spec` (evidence in order: the page's `url` query, which decides; Redoc/Scalar attributes and Swagger UI config documents; then quoted spec URLs in the page and its initializer — Swagger's Petstore demo hosts never count) (a named URL that doesn't load or parse as OpenAPI drops out; several parse-proven specs, or none, exit 2 listing what was found — never a pick among specs), then the **tell-based** detectors, then `<meta name="generator">` (every tag, since a platform often names itself after its framework — Starlight's page carries `Astro` first), then fallback tells: `_static/` assets (Sphinx), a `search/search_index.json` (MkDocs — the index is then also the acquisition source: pages are rebuilt from its records, not crawled, which costs fidelity: the index stores flattened plain text, so code blocks lose their fencing), the nearest `llms.txt` at or above the URL's path that lists per-page `.md` links (a docs subpath often publishes its own index, and the site root's lists other pages; when that index sits above the URL and lists pages beneath it, only the URL's section is staged). That rung delegates to the gitbook machinery, which caps at 1000 pages and fetches each page's rendered twin for GitBook's image-proxy resolution unless a generator tag names another platform — Mintlify, Fern and similar hosts serve clean markdown, and their rendered pages are hundreds of KB each. Their markdown still carries what the platform adds for AI clients — a leading "fetch the documentation index" note or YAML front matter before the first heading, top-level MDX `import`/`export` component definitions — so `_gitbook.strip_boilerplate` removes those (MDX only outside code fences, and never past a prose line) and page-relative links resolve against each page's URL. Do not rewrite anything inside fenced or indented code blocks or inline code spans — `obj[key](arg)` is code, not a link (`_md_code` tracks where code sits). A site none of these recognise raises `InvalidInputError` naming what was probed (CLI exit 2).

   **A same-site meta-refresh entry page is followed before the ladder runs** — Writerside's entry pages are such shells, and the target, not the shell, carries the tells. A refresh in `<noscript>`, or a delayed one (a session timeout), is not a shell and is not followed. **A platform that can drop its generator tag gets a layout tell placed after the generator-tag strategies** (Antora, Starlight, VitePress, Docsy's page shell), so a page another generator tagged keeps that route, and before the probes that cost a request. Docsify's tell sits last among the free rungs, because a Docsify shell answers every unknown path and would fool the probes below it. Each strategy discovers its pages from the most complete ordered source the platform publishes:

   - mdBook: `print.html`, the whole book in one fetch; the sidebar TOC drives a crawl when the book disables it.
   - Writerside: `HelpTOC.json`, reading order and nesting included; the entry page is never trusted for discovery.
   - MadCap Flare: the TOC file `Data/HelpSystem.xml` names, plus its chunk files — `define({...})` JS literals, not JSON, read by `_flare_toc` — in tree order with nesting. A linkless book or a link out of the manual becomes a heading only when topics sit under it; a link to a bookmark names its topic only where the tree never links the topic itself; a topic the tree places twice is staged once. A topic skipped as a repeat, a duplicate or a failed fetch still heads the topics under it, so they never re-parent. Each topic is its `#mc-main-content`: script-only hotspots keep their label without the link, skin icons and hover definitions go, a related-topics control becomes the links it lists, and a code snippet becomes plain code in its language.
   - Fluid Topics: the khub API the app shell loads — `api/khub/maps` names the publication whose `ft:prettyUrl` is the longest prefix of the decoded `/r/` path (a `/reader/<map>/` URL names it directly), and a seed that runs past that publication's root must name one of its topics — otherwise the match was a shorter, umbrella publication and the seed is refused. `…/toc` gives every topic in tree order, and each topic's content is a fragment with no title, so the TOC title becomes its heading: content reused under another title is staged under each, a duplicate is the same title *and* body, and a title-only node heads the topics under it. A node's `/r/…` URL is rooted at the tenant base unless it already names the tenant's path. Inline `data:` images, base64 or percent-encoded, are decoded into `raw/images/` and bundled beside the deliverable; one that does not decode is dropped with a warning. Internal links (spans naming a TOC node) point at reader pages, and a skipped or empty topic heads only the topics under it, as in Flare. Expect a portal's robots.txt to disallow these API paths: Fluid Topics' own documentation portal does, and its allow-list reads as the platform default.
   - Antora: the nav of the one component version the URL names, then pages only the component's sitemap lists (those carrying an `h1.page` title — generated tag listings have none); the site sitemap spans every version and is alphabetical, so it adds pages but never sets the order.
   - Starlight: the sitemap, in sidebar order; when the sidebar has groups, only a grouped entry adopts pages the sidebar omits, since a top-level link beside groups is site navigation (a blog).
   - VitePress: the server-rendered sidebars, the entry's section first.
   - Docsify: the raw markdown the sidebar file lists, routed as the runtime routes it (`basePath`, `alias`, `routerMode` read from `window.$docsify`), plus pages only another page's text links to, staged after it — kept to directories the sidebar covers, so a README's link to its translation stays out.
   - MediaWiki: the action API — the seed page plus the pages its content links to, one hop, in link order.
   - Docsy: the Hugo crawl, in the theme sidebar's order.

   **Tell-based detectors run before the generator sniff** because those systems have two faces: the entry page a reader lands on advertises differently from the topic pages that carry the content. ClickHelp publishes no generator meta at all; a Paligo *portal* shell carries none (only its topics do); a SCHEMA ST4 entry page advertises the publisher's own stylesheet rather than `ST4`. MadCap Flare writes no generator meta either: its runtime attributes (`data-mc-*`) sit on every page's `<html>`, and its entry shell can have an empty body. A Fluid Topics portal answers every URL with the same app shell, told by its `ft-tenant-base-url` meta, its `fluidtopicsclient` script, or its page script beside the app loader — that script alone could be an embed on another site. Probing the landing URL for a generator therefore identifies nothing, and the manual reads as an unrecognized site.

   **Content-container selectors are ordered, most-specific first — never grouped.** A publisher who renames the real container keeps the generator's stock id on an *outer* wrapper that also holds the search widget and nav. A grouped selector (`#content, #contentOrg`) returns whichever comes first in document order, which is the wrapper, so the chrome ships inside every page. This passes any fixture that treats the two ids as alternatives and only fails against the real source — check it with a live ingest, not a unit test.

So `classify` reporting `docs_probe` means "will content-probe at acquire" — not a confirmed source type. `classify` alone therefore cannot prove a URL is unroutable; `classify --probe` (or `ingest`) can, since it runs the fetch-and-sniff ladder in `_detect.detect`. `classify` returns `None` only for a non-web argument (a local file path or `file://` URL) — every http(s) URL has a match by the time `docs_probe` is reached.

`api_spec` and `docs_probe` are the two patterns that match on **content shape** rather than host, following the same precedent: a cheap `match`, then a content-sniffing `acquire`. `api_spec`'s `match` is the usual cheap path check, but OpenAPI-vs-Postman can't be told from a URL — so `acquire` fetches the file and *content-sniffs* it: an `openapi`/`swagger` key ⇒ OpenAPI, `info` + `item` ⇒ Postman, neither ⇒ a clean `InvalidInputError` (CLI exit 2). It emits `kind="markdown"`, rendering the spec's endpoints, params, and responses (or the collection's requests) into one file instead of crawling pages. Its path check also claims the UI pages that render specs (`/swagger-ui.html`, `/swagger/`), so when an http(s) URL serves HTML, `acquire` hands a Swagger UI/Redoc/Scalar page to the same spec discovery `docs_probe` uses and ingests the spec it names. It also accepts a **local file path**, since a spec is often behind a ReDoc/Swagger-UI "Download" button rather than at a stable URL.

Check a URL's routing with `pagespring classify <url>`, and where `docs_probe` would hand it with `classify --probe`; list what's registered with `pagespring patterns`. **`acquire` waits the polite delay once before every hand-off that fetches** — the strategy's first request follows the probe's last.

**A platform with no pattern named for it may already be supported.** `docs_probe` routes by what a page carries — a generator tag, an `llms.txt` index, an API reference UI — so the absence of a module or string naming a platform proves nothing. Do not propose a pattern for a platform on the strength of a name search in `src/`. Prove it can't route first: ingest a real URL into a scratch `INCOMING_DIR` and read what dispatched. Platforms already served this way are pinned by name in `tests/test_docs_probe.py` (`test_platforms_without_a_pattern_of_their_own_route_through_existing_rungs`); add a case there when a live check shows another one routing.

## Fetching

All network I/O goes through `pagespring.http`, a thin shim over `pf_core.fetch` (stdlib `urllib`). **Never add `httpx` or `requests`.** The shim owns what is pagespring's: the identifying `pagespring/<version>` User-Agent (`PAGESPRING_UA` overrides it for a source that mishandles tool UAs), the `timeout=` keyword the patterns pass, `polite_sleep()` between crawl requests, and a per-fetch size cap with separate budgets for text and binary downloads (`PAGESPRING_MAX_TEXT_BYTES` / `PAGESPRING_MAX_DOWNLOAD_BYTES` override the defaults in `http.py`; an archive's extracted size has its own budget, checked against the sizes its members declare before anything is written — `PAGESPRING_MAX_EXTRACT_BYTES` overrides the 2 GiB default). The cap bounds the decoded body as well as the wire read, so an overrun surfaces as `ClientError` → `AcquireError` → CLI exit 4 instead of exhausting memory as it inflates. The fetch core owns the transport: status-aware retries (permanent 4xx fail fast; 429 honours `Retry-After`, capped; 5xx and network errors back off), charset resolved from the response, cache validators, and manual redirect walking.

Two properties patterns are written against. **Raw `urllib` exceptions propagate unwrapped**, which is what lets a pattern branch on `HTTPError.code` (readthedocs' 404 PDF fallback, the microsoft_support 403 cooldown). And **URLs are SSRF-guarded** — on the initial request and every redirect hop, a URL that resolves to a private, loopback, link-local, or unresolvable address raises `InvalidInputError` before any request goes out (CLI exit 2); `URL_FETCH_ALLOW_PRIVATE=1` opts out for a deliberately internal source.

Patterns log-and-skip individual page failures rather than aborting a whole crawl, so one dead topic page doesn't lose the manual. See the README's *Intended use* section for the client-behavior stance (public docs only, no auth/evasion, robots.txt position).

## Adding a new pattern

1. Write `src/pagespring/patterns/<name>.py` implementing the four-member `Pattern` protocol.
2. Register the instance in `registry.py`, respecting the [classification order](#classification-order): host-specific first, extension/content next, then `gitbook` — and **before** `docs_probe`, which must stay last or its catch-all shadows every pattern registered after it.
3. Keep all fetching in `pagespring.http`, and leave asset URLs **absolute** so pagespeak can pull them during convert.
4. Call `_site.flatten_responsive_images(node)` immediately before `absolutize_refs` — without it, every `<picture>`/`srcset`/`data-src` reference the source uses ships remote and no `localize` run can reach it.
5. If the pattern derives a base directory from the entry URL, use `_site.names_a_file` — `docs_probe` hands over `url.rstrip("/")`, so a directory seed arrives suffix-less and an unconditional strip scopes the crawl to the *parent*, where every sibling 404s. Re-add the trailing slash before crawling too: the entry URL is also the `urljoin` base for `absolutize_refs`, so without it every relative asset resolves one level too high. Anchor on the **post-redirect** URL, and re-check scope after each fetch — an in-scope href can still redirect out.
6. Set `AcquireResult.pages` to the count of source units the deliverable covers (crawl pages / articles / PDF pages) — `ingest` surfaces it, which is how coverage gaps get caught. Use `None` when it genuinely can't be determined; never substitute a placeholder like `1`, which reads as real and hides the gap. PDF patterns get theirs from `patterns/_pdf.page_count`.
7. If the source caps or truncates a crawl, `log.warning` it — a silently truncated crawl reads as a complete one. Report pages discovered but never staged as `lost`; `truncated` only ever means the page *cap*, so a crawl bled dry by errors otherwise reads as complete.
8. Declare the signals `audit` and `refresh` read, none of which is on the `Pattern` protocol (they are read via `getattr`, so nothing flags their absence): `single_fetch = True` when the deliverable derives from exactly the one recorded URL — it suppresses `single_page_crawl` and admits the conditional-GET fast path — and `AcquireResult.single_document` when the source **is** one article, so a `pages: 1` deliverable is correct rather than a collapsed crawl. Omitting `single_fetch` is what made a one-operation API spec audit as a collapsed crawl.
9.
